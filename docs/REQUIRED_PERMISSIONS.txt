================================================================================
AMAZON QUICK OBSERVABILITY PLATFORM
AWS IAM PERMISSION MODEL
================================================================================

Audience: security and cloud administrators reviewing Terraform deployment access.

`docs/iam-policy.yaml` is a deployer-policy baseline. It does not include
runtime permissions; Terraform installs scoped inline policies on runtime roles.
Apply organization controls such as permission boundaries, SCPs, approved tag
conditions, and resource-prefix scoping before production use.

--------------------------------------------------------------------------------
1. TERRAFORM DEPLOYER
--------------------------------------------------------------------------------

The Terraform identity manages:

  - KMS key, alias, rotation, key policy, tags, and deletion lifecycle
  - CloudWatch log groups, vended-log delivery, and subscription filters
  - two S3 buckets and their policy/encryption/versioning/public-access config
  - four Lambda functions and two resource-based invoke permissions
  - five Firehose streams and two EventBridge rules/targets
  - service IAM roles and inline role policies
  - one Athena workgroup and one CloudFormation lifecycle-bridge stack

It also calls `sts:GetCallerIdentity` and
`quicksight:AllowVendedLogDeliveryForResource`.

The exact baseline actions are in `iam-policy.yaml`; `permissions-list.txt`
contains the matching flattened Action inventory. The policy includes provider
read/delete calls required by pinned AWS provider 6.33.0.

`iam:PassRole` is restricted to Lambda, Firehose, CloudWatch Logs, and
EventBridge. Before production approval, scope role-management and PassRole
resources to the generated role ARNs for the chosen prefix. Scope other
statements to known account, Region, bucket, key, and stack ARNs where possible.

The baseline intentionally excludes Glue/Athena catalog execution, QuickSight
asset lifecycle actions, SSM ownership markers, S3 data-object access, and KMS
cryptographic access. Those are runtime responsibilities described below.
Lake Formation administration is outside this repository's Terraform workflow.

--------------------------------------------------------------------------------
2. TERRAFORM-MANAGED RUNTIME PRINCIPALS
--------------------------------------------------------------------------------

Terraform creates the following role policies in `terraform/11-security-iam.tf`.
Possession of `iam:PutRolePolicy` lets the deployer install these policies, but
does not grant their runtime actions to the deployer identity.

TerraformProvisioner Lambda
  - CloudWatch Logs write access to its log group
  - SSM ownership markers under `/quick-observability/*`
  - Athena DDL on the managed workgroup and Glue catalog management
  - scoped S3 and Athena-results access
  - KMS cryptographic access on the deployment key
  - QuickSight lifecycle operations for the theme, data source, seven datasets,
    analysis, dashboard, and topic

LicensedUsersSnapshot Lambda
  - CloudWatch Logs write access
  - `quicksight:ListUsers`
  - `s3:PutObject` only under `licensed-users-snapshot/*`
  - KMS Encrypt/GenerateDataKey on the deployment key

Transform, Firehose, CloudWatch Logs delivery, and EventBridge roles are scoped
to their log, stream, Lambda, S3-prefix, and KMS requirements. Terraform also
creates a dedicated QuickSight Athena data-source run-as role with scoped
Athena, Glue, S3, and KMS access.

--------------------------------------------------------------------------------
3. CLOUDFORMATION CUSTOM-RESOURCE BOUNDARY
--------------------------------------------------------------------------------

The CloudFormation stack contains two custom resources only. CloudFormation
invokes the provisioner through a Lambda permission restricted to
`cloudformation.amazonaws.com` and the source account. Sending a response to
the presigned ResponseURL requires no IAM action.

Delete depends on successful provisioner cleanup. A timeout or failed
QuickSight/Athena operation can block `terraform destroy`.

--------------------------------------------------------------------------------
4. ACCOUNT PREREQUISITES
--------------------------------------------------------------------------------

  - An active Amazon Quick/QuickSight subscription in the target Region.
  - A valid QuickSight owner user ARN in the selected namespace.
  - Permission to create and pass the dedicated QuickSight Athena run-as role.
  - No SCP, permission boundary, KMS policy, or QuickSight IAM policy assignment
    that denies required calls.

--------------------------------------------------------------------------------
5. APPROVED TERRAFORM DESTROY
--------------------------------------------------------------------------------

Default lifecycle guards prevent bucket and KMS deletion. An approved full
destroy also requires the S3 object/version/multipart cleanup actions in
`iam-policy.yaml`. Set `force_destroy_buckets = true`, apply it, back up data,
remove the three local `prevent_destroy` guards, then run destroy. Never delete
a key while retained encrypted objects depend on it.

--------------------------------------------------------------------------------
6. REVIEW LIMITATIONS
--------------------------------------------------------------------------------

The baseline was reconciled with the repository and pinned Terraform AWS
provider 6.33.0. Provider upgrades can add API calls. Before changing provider
versions or organizational controls, test init/plan/apply/destroy in an isolated
account and use CloudTrail denied events to reconcile the reviewed policy.
